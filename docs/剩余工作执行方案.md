按「卫生先行 → 2d → P2 成熟优先批次」收尾 `优化方案总览.md` 全部遗留项。

## 2. 批次 0 · 卫生组 + P3 备忘

| 项 | 做法 | 验收 |

| `com.bloom.util.Function` 命名规范化 | 先澄清实际指代：`Functions`/`Util` 存在同名方法 `getClassBytes`（类双体重复）。方案：合并为单一工具类或按职责改名，全仓库 import 跟进 | 52 用例绿 |

## 3. 批次 1 · 2d MemShellParty 对接（零新依赖）

- 路由形态：`[gadget链]/memshell/GEN:{server}/{tool}/{type}`，`GEN:` 前缀命令原样传入链，RouteParser 不特殊化。
- 新增 `GenMemshellResolver`：按 server×tool×type 组合查内置字节表（`gen/` 资源目录预生成 .class bytes 打包进 jar），未命中明确报错"无该组合"。
- `Gadgets.createTemplatesImpl` 增加 `GEN:` 分支：取表内 bytes 走 TemplatesImpl 注入，与 `CLASS:`/`FILE:` 并列。
- v1 覆盖：仓库现有 9 个预缓存模板按 server=tomcat × tool=cmd/behinder/godzilla × type=filter/listener/servlet 可映射组合优先，其余组合明确拒绝。
- 验收：dry-run 解析、序列化流头部断言、集成测试条目含 `javaSerializedData`、未命中组合报错可见。

## 4. 批次 2/3 · P2 扩链（成熟优先）

每链统一五步：

1. `ChainRegistry` 注册生成器
2. `ChainMeta` 能力声明（动作/依赖/JDK 区间）
3. `ChainRegistrySmokeTest` 冒烟命令
4. golden 追加新行（输出确定的链）
5. 能力矩阵 / `-u` 输出同步

批次划分：

- **批次 2（成熟链）**：H2（三载体 + JRE Soundbank）、PostgreSQL socketFactory、MySQL（反序列化 4 段 + 客户端文件读）、Fastjson1、Fastjson2。均有公开参考实现（JNDIMap 等）。
- **批次 3（其余）**：Derby、Databricks、HikariCP/Vibur、MLet、NativeLibLoader、Tomcat Blind XXE、Hessian、Jackson（8/17A/17B 变体）、对抗投递（UTF-8 Overlong、混淆类名、Nashorn/JShell 自定义 payload）。

补充规则：

- BeanFactory/Reference 系新链复用 `RefFactory` 分支结构，自动获得直返能力。
- 只能走序列化载体的链，在 `ChainMeta` 的 JDK 区间显式标注 trustSerialData 约束。
- 每批一次或数 commit（按链分组），批末跑总验收。

## 5. 风险与决策点

| 风险/决策 | 处理 |
|---|---|
| golden 基准已冻结（`writeGolden` 抛异常） | 批次 2 开工时新增"仅追加"流程：新链行生成后人工核对入基准，旧行不触 |
| MemShellParty 组合空间远大于 v1 覆盖 | v1 只映射仓库现有模板；扩充依据使用反馈，不一次性膨胀 |
| `Function` 命名规范化的真实指代 | 批次 0 开工第一步澄清，方案定稿后再动手 |
| 新链需要新增 Maven 依赖（如 fastjson2、hessian） | 出范围新增依赖，逐条停下请示，与瘦身的剔除项对账 |
| 对抗投递类链（混淆/编码绕过）行为敏感 | 单独立票，验收先结构级，实测标靶机待办 |
